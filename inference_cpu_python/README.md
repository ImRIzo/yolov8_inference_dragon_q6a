# YOLOv8 Video Inference on CPU (onnxruntime)

Real-time YOLOv8 object detection on video files using the CPU through
`onnxruntime`.  Python port of the Radxa Q6A NPU C++ tool — same pipeline,
same CLI, same reports — just running on the CPU instead of the QNN HTP.
Displays a live OpenCV window with bounding boxes, FPS counter
(smoothed + min/max), per-frame pipeline timing, and saves a benchmark
report on exit.

---

## Requirements

- Any aarch64 / x86_64 Linux (tested on Radxa Dragon Q6A, Ubuntu 24.04)
- Python 3.10+ with the `py312` pyenv environment (preinstalled with all
  dependencies), or any venv with the packages below
- A YOLOv8 `.onnx` model (e.g. `best.onnx`, Ultralytics export)

```bash
pip install -r requirements.txt
```

If the system Python is externally managed (PEP 668), use a venv or the
preconfigured pyenv environment — `run.sh` does this automatically.

### Static labeled-image evaluation (accuracy)

Runs the same CPU pipeline on every image of a labeled test set, saves the
raw detections and computes Ultralytics-exact metrics — the same flow as
the C++ NPU tool (`yolov8_video --eval`), so both runtimes can be compared
through the identical metric pipeline.

**Test-set evaluation — exact copy-paste command:**

```bash
cd inference_cpu_python

./run.sh --eval --images ../data/test/images --labels ../data/test/labels \
    --out ../results/cpu/test
```

(with `../data/` being the dataset folder next to the repository root.)

Evaluation settings default to **Ultralytics val.py values**: conf `0.001`,
NMS IoU `0.70`, max detections `300`, 5 warm-up images (warm-up predictions
still count for accuracy, only their timings are excluded).  The pipeline
per image:

```
letterbox 640x640 → ONNX CPU inference → YOLO decode → NMS → max-det cap →
reverse letterbox back to original image pixels
```

Every run writes, into the output directory (`--out`, default: script dir):

| File | Content |
|---|---|
| `predictions.csv` | Raw detections after NMS + reverse letterbox: `image,class_id,confidence,x1,y1,x2,y2` (full float precision) |
| `image_sizes.csv` | `image,width,height` for every evaluated image |
| `eval_config.csv` | Runtime/backend, model path, input resolution, thresholds, max_det, warm-up, dataset dirs, date |
| `evaluated_images.txt` | Exact filenames evaluated |
| `eval_report_<dataset>.txt` | Full report: metrics, per-IoU AP table, per-class table, timing (mean/std/min/max), filename list |
| `evaluation_results.csv` | Final metrics table (written by `evaluate_metrics.py`) |

### Ultralytics-exact metrics (evaluate_metrics.py)

The script prints its own built-in COCO-style metrics, but the canonical
numbers for the FP32-vs-INT8 comparison come from the shared
`evaluate_metrics.py` (repo root), which reproduces **Ultralytics 8.4.45
val.py exactly** (same matching, `ap_per_class`, 101-point AP, max-F1
operating point).  It is run automatically at the end of `--eval`, or
manually anytime without re-running inference:

```bash
python3 ../evaluate_metrics.py \
    --predictions ../results/cpu/test/predictions.csv \
    --labels ../data/test/labels \
    --images ../data/test/images \
    --sizes ../results/cpu/test/image_sizes.csv \
    --config ../results/cpu/test/eval_config.csv \
    --output ../results/cpu/test/evaluation_results.csv
```

### FP32 vs INT8 ONNX

This script runs **any ONNX** via onnxruntime's CPUExecutionProvider:
the bundled FP32 `best.onnx`, or an INT8 QDQ ONNX quantized with the
standard `onnxruntime.quantization` tool (see the INT8 quantization
section below).  QNN-specific quantized artifacts/`.bin` files are not
loadable here — those go through the C++ NPU tool.

## INT8 quantization (quantize_onnx.py)

`quantize_onnx.py` converts `best.onnx` (float32) into a standard INT8
ONNX that runs on the CPU through onnxruntime's `CPUExecutionProvider`.
Two modes are offered:

| Mode | What gets quantized | Needs calibration images? | Speed on Q6A |
|---|---|---|---|
| **static QDQ** (default) | weights **and** activations | yes | **~4× faster than FP32** |
| dynamic | weights only (activations stay float32) | no | *slower* than FP32 on ARM |

Always prefer **static** on this board.  Dynamic exists only as a
fallback when you have no calibration images — on ARM it dequantizes the
weights back to float for every layer, which is slower than just running
the float32 model.

### Quick start

```bash
cd inference_cpu_python

# Static QDQ INT8 (recommended) — calibrates on the train split by default
PYENV_VERSION=py312 python3 quantize_onnx.py --num-calib 128 --verify 12

# Higher quality: more calibration images + Entropy calibration
PYENV_VERSION=py312 python3 quantize_onnx.py \
    --calib-dir ../data/train/images --num-calib 256 --calib-method Entropy

# Dynamic (weights-only) INT8 — no calibration images needed
PYENV_VERSION=py312 python3 quantize_onnx.py --mode dynamic
```

Output: `best_int8.onnx` (static) or `best_int8_dyn.onnx` (dynamic).
Calibrate on `train` — never on the split you evaluate on.

### How the static quantization works

`quantize_onnx.py` calls onnxruntime's `quantize_static`.  The whole
conversion is a four-step process:

**1. Calibration** — 128 images from `../data/train/images` (default) are
preprocessed with the **exact same letterbox pipeline** as
`yolov8_cpu.py` (resize to 640×640, RGB, `/255`, NCHW float32, pad 114),
so the value ranges the quantizer sees are the same ranges the model sees
in production.

**2. Range collection** — the float32 model is run over every calibration
blob and the observed `min`/`max` of *every tensor in the graph* is
recorded (MinMax calibration; Entropy histograms are also available via
`--calib-method Entropy`).

**3. Scale / zero-point computation** — each tensor's range is turned into
two constants that map floats to 8-bit integers:

```
scale      = (max − min) / 255          # uint8
zero_point = round(−min / scale)
x_float    ≈ (q − zero_point) × scale   # q is the 8-bit integer
```

Weights are quantized **per-channel** (each conv output channel gets its
own scale, much better accuracy than one scale for the whole filter),
activations per-tensor as uint8.

**4. Graph rewrite (QDQ)** — the float32 graph is rewritten so every
quantized op is wrapped in a `QuantizeLinear`/`DequantizeLinear` pair:

```
original:   ... → Conv(fp32) → ...
quantized:  ... → QuantizeLinear → Conv(int8) → DequantizeLinear → ...
```

The model's **input and output stay float32** — only the middle is 8-bit.
That is why it is a drop-in replacement: the letterbox preprocessing, the
NMS, the drawing and the whole `--eval` pipeline work unchanged, just
pass `--model best_int8.onnx`.

### The YOLOv8 decode-head fix

YOLOv8 exports bake the decode head (DFL boxes + sigmoid scores) into the
graph.  A naive `quantize_static` puts a single uint8 scale on the head's
final `Concat` output, which mixes **box coordinates (0–640)** and
**scores (0–1)** in one tensor.  With `scale = 2.736, zero_point = 5`
(calibrated for the box range), every score rounds to the zero point:

```
score 0.86 →  q = round(0.86 / 2.736) + 5 = 5  →  x = (5 − 5) × 2.736 = 0.0
```

→ the model detected **nothing**.  `quantize_onnx.py` fixes this by
passing `OpTypesToExcludeOutputQuantization` for the head's elementwise
and latent ops (`Concat, Sigmoid, Slice, Sub, Div, Add, Mul, Reshape,
Split, Transpose, Resize, MaxPool, Softmax`): those op **outputs** stay
float32, while all 64 Convs remain fully quantized — that is where
essentially all of the compute lives.

### Verification (--verify)

After quantization the script loads both models and compares them on the
first N calibration images: cosine similarity of the raw outputs and
NMS'd detection matching (IoU > 0.5, conf 0.25) through the same decode
code the evaluator uses.  Typical result:

```
cosine similarity  : mean 0.999906  min 0.999816
detections (0.25)  : fp32 21  int8 23  matched 21 (100.0% of fp32)
```

### quantize_onnx.py options

| Option | Default | Description |
|---|---|---|
| `--model` | `./best.onnx` | Input float32 ONNX |
| `--output` | `<model>_int8.onnx` | Output INT8 ONNX (`_int8_dyn` for dynamic) |
| `--mode` | `static` | `static` (QDQ, calibration) or `dynamic` (weights-only) |
| `--calib-dir` | `../data/train/images` | Calibration images directory (falls back to valid/images) |
| `--num-calib` | `64` | Number of calibration images |
| `--calib-method` | `minmax` | `minmax` or `entropy` |
| `--act-type` | `QUInt8` | Activation quantization type |
| `--wt-type` | `QInt8` | Weight quantization type |
| `--per-channel` / `--no-per-channel` | on | Per-channel weight quantization |
| `--verify` | `16` | Compare INT8 vs FP32 on N calibration images (0 = skip) |

### Evaluating the INT8 model

No new evaluator is needed — `best_int8.onnx` is a drop-in for
`best.onnx`:

```bash
./run.sh --eval --model best_int8.onnx \
    --images ../data/test/images --labels ../data/test/labels \
    --out ../results/cpu_int8/test
```

Measured on the Q6A (42-image `test` split, conf 0.001 / IoU 0.7,
Ultralytics-exact metrics):

| Model | Size | Inference | mAP@0.5 | mAP@0.5:0.95 | Precision | Recall | F1 |
|---|---|---|---|---|---|---|---|
| `best.onnx` (float32) | 12.3 MB | 267 ms | **0.6350** | **0.3821** | **0.6245** | 0.6800 | **0.6511** |
| `best_int8.onnx` (static QDQ) | 3.5 MB | **67 ms** (4.0×) | 0.6135 | 0.3645 | 0.5691 | 0.6868 | 0.6224 |
| `best_int8_dyn.onnx` (dynamic) | 3.4 MB | ~506 ms | ≈ FP32 accuracy, but slower than FP32 on ARM | | | | |

### Legacy `--map` mode

`--map DATADIR` still works for dataset folders containing `images/` +
`labels/` and behaves like `--eval` without the CSV exports:

```bash
./run.sh --map data/test --names Ganoderma --conf 0.001 --iou 0.7
```

The model's input size, output layout and class count are read from the
ONNX metadata automatically, so each model's own geometry is applied —
nothing to configure.  Only the class *names* may need `--names`: the
bundled model is 1-class (`Ganoderma`), so pass `--names Ganoderma` for
human-readable labels and eval tables (otherwise it shows `class_0`).

### Measured results — CPU float32 vs CPU int8 vs NPU int8

Same `valid` split (104 images, 126 GT boxes), conf 0.001 / NMS IoU 0.7 /
max det 300:

| Backend | Weights | mAP@0.5 | mAP@0.5:0.95 | Precision | Recall | F1 |
|---|---|---|---|---|---|---|
| CPU (this repo) | float32 `.onnx` | **0.8188** | **0.5271** | **0.6918** | 0.8016 | **0.7426** |
| CPU (this repo) | static int8 `.onnx` (`quantize_onnx.py`) | 0.7428 | 0.4365 | 0.6124 | **0.8333** | 0.7060 |
| QNN HTP (NPU repo) | int8 `.bin` | 0.6980 | 0.3488 | 0.5652 | 0.7222 | 0.6341 |

The CPU float32 row is the unquantized reference.  The CPU static-int8
row is the same `best.onnx` quantized by `quantize_onnx.py` (weights +
activations int8, calibrated on the `train` split) — it costs ~0.08
mAP@0.5 but runs ~3.7× faster than float32 on the CPU and even beats the
NPU's int8 conversion on this split.  All three use the same
preprocessing, NMS and metrics, so the numbers are directly comparable.
(The NPU model is a different training checkpoint, so treat that gap as
an upper bound of the quantization cost, not an exact measure of it.)

mAP matching is strict: a detection counts only if it overlaps its ground
truth with IoU > threshold, and duplicate predictions count as false
positives, so a few near-miss boxes measurably lower the score.

## Performance

Tested on Radxa Dragon Q6A (QCS6490) with 640x640 input video,
`best.onnx` (YOLOv8n-scale, 1 class) on the 8 Kryo CPU cores:

| Metric | float32 | static int8 |
|---|---|---|
| Preprocess (letterbox + RGB + NCHW) | ~3.9 ms | ~2.5 ms |
| **Inference (CPU)** | **~240–267 ms** | **~63–71 ms** |
| Postprocess (parse + NMS + draw) | ~0.4 ms | ~0.6 ms |
| **Pipeline total per frame** | **~244–270 ms** | **~66–75 ms** |
| **Wall-clock FPS (headless)** | **~4.1** | **~13–15** |

The int8 column is `best_int8.onnx` from `quantize_onnx.py` (static QDQ,
weights + activations).  For reference, the same pipeline on the QCS6490
NPU runs at ~13 ms inference / ~21 FPS.  The CPU version is the accuracy
reference and the NPU fallback; use the NPU repo for real-time, or the
CPU int8 model for a ~4× CPU speedup at a small accuracy cost.

Display overhead (`cv2.imshow` + `cv2.waitKey`) is significant on the Q6A.
Use `--no-show` for accurate pipeline benchmarking.

## Troubleshooting

**`ModuleNotFoundError: No module named 'onnxruntime'`**
Run through `./run.sh` (uses the `py312` pyenv environment), or install
into your venv: `pip install -r requirements.txt`.

**`externally-managed-environment` error from pip**
Debian/Ubuntu PEP 668 protection.  Use a venv
(`python3 -m venv .venv && .venv/bin/pip install ...`) or the existing
pyenv environment via `run.sh`.

**Wrong class names in the boxes**
The bundled model has one class but the name is not stored in the ONNX
metadata, so the default label is `class_0`.  Pass `--names Ganoderma`
(or a `names.txt` file, one name per line) to label it properly.

**Qt font warnings when the window opens**
Harmless — OpenCV's Qt backend prints font directory warnings on Wayland.
The window still renders; install `fonts-dejavu-core` to silence them.

**Flickering / double boxes**
Adjust IoU: `--iou 0.3` (more aggressive) or `--iou 0.7` (looser).

**Low FPS**
Expected on CPU — float32 inference is ~247 ms/frame.  Options:
quantize to int8 (`quantize_onnx.py`, ~4× faster, see the INT8 section),
smaller model (`yolov8n` or a P6 variant), lower video resolution, or
`--no-show` for benchmarking.  For real-time, use the Q6A NPU version of
this repo.

**`Could not determine class count` on a custom export**
The script handles the standard Ultralytics layouts
(`[1, 4+NC, A]`, `[1, A, 4+NC]`, and two-output boxes+scores).  If yours
is dynamic-shaped, export again with a fixed imgsz:
`model.export(format="onnx", imgsz=640, dynamic=False)`.

**`quantize_onnx.py` fails with `No module named onnx`**
Install `onnx` explicitly (`pip install onnx`, or update to the current
`requirements.txt` which includes it).  onnxruntime bundles a copy of
onnx internally, but the quantization script imports the package
directly.

**`quantize_onnx.py`: calibration dir not found**
Static quantization needs calibration images.  Point `--calib-dir` at a
folder of images (e.g. `../data/valid/images`), or use
`--mode dynamic` to skip calibration entirely (slower on ARM, see the
INT8 section).
